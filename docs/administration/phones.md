Damvia shows a separate interface on screens narrower than 768 px. It uses the same address, sign-in and API as the computer version, so a link shared from a phone opens the same collection, product or search on a computer, and every access rule applies unchanged. This page tells you what your users can do on a phone and what they are sent back to a computer for.

## Five tabs

| Tab | Shows |
|---|---|
| **Home** | The menu item marked as home, as on a computer. Guests land on their first collection. |
| **Library** | The menu, one level per screen. Sections become headings and dividers become space. Collections a person cannot open are not listed. Guests see the collections shared with them. |
| **Search** | One search field for files or for your records (the tab uses your record label). A **Filters** screen holds sort, file type, format, size, dates, record fields, variants and file metadata, and changes the results only when **Apply** is pressed. A search link copied from a computer keeps all its criteria. |
| **Saved** | Favorites and the person's own collections. Not shown to guests. |
| **Account** | Profile, **Downloads**, sign out, and for managers and admins **Users** and, for admins, **Library status**. A badge counts the people waiting for approval. |

## What people do on a phone

- Open a file full screen, swipe to the next one and tap a record value to copy it. The phone's Back gesture closes the preview.
- Select several files with **Select**, then download them or add them to a collection.
- Download: **Download now** up to 1 GB, **Email me a link** above it. The usage terms must be accepted first, as on a computer. See [Downloads](./downloads.md).
- Copy a ready download link, or pass it to the phone's share sheet, from **Downloads**. Anyone who receives the link can download the files until it expires, and it stops working if the sender loses access or is suspended.
- Favorite files and collections, create a collection, and share one they own by email or with a copied invitation link. See [Collections and sharing](./collections-and-sharing.md).

## What managers and admins do on a phone

- **Users**: search people and open **Needs approval**, **Active**, **Unverified** or **Suspended**. A person's screen offers **Approve**, groups, **Suspend access** or **Restore access**, **Resend verification email** and **Send password reset**. Admins also change role and region. The link in the approval request email opens this screen. The rules are the same as on a computer; see [Users and approval](./users-and-approval.md).
- **Library status** (admins): the dashboard's list of items that need attention, storage use with **Measure now**, cloud source health, and **Retry pending files** when files wait to be processed. See [Dashboard](./dashboard.md).

## What stays on a computer

A phone shows **Open this on a computer**, with a button to copy the link, for the page editor, collection settings and action-bar rules, the record spreadsheet and imports, variants, asset types and matching, licences, groups, regions, authorized domains, menu, settings, Insights and every other admin screen. Account deletion, two-step verification, active sessions, display preferences, saved filter layouts and custom spreadsheet exports are also computer-only.

## Access on a phone is the access on a computer

The phone screens call the same server procedures, and the server checks roles, approval, groups, invitations, drafts and licences on every call. Screens limited to some roles send other people home, but that is a convenience; the server refuses their data anyway. The phone interface does not keep files for offline use. Signing out clears cached lists, recent searches and the selection, so the next person on a shared phone starts clean.
